# @local/for-free

免 Key 的免费模型接入：装进 DSH 就有两条免费车道，模型出现在选择器的「For Free」分组里，不用登录、不用填 Key。

- **opencode 免费车道** —— `opencode.ai/inference/v1/*`，需要按上游客户端的指纹发请求（UA、会话编码、`read`/`shell` 两个工具定义必须逐字一致）。清单能拉到时模型就出现；上游对本出口限流（429）时全部转红，恢复后自动回来。
- **Kilo 免费池** —— `api.kilo.ai/api/gateway`，公开网关、零凭据。它是目前最稳的一条：实测 `cost = 0`，正常流式出正文。

## 安装

这仓库里的插件都用 `plugin_manager` 以 `link:` 方式装进 profile：

```
install_bundle  /Volumes/TUF ESD-T1A Media/dsh-plugins/for-free
```

装完重启 DSH（宿主半要重新加载）。设置 → 插件里出现「For Free」，模型选择器里出现「For Free」分组。

> `plugin_manager` 不是每个会话都有。没有它的会话：换一个有插件开发技能的会话，说一句「install_bundle 装 /Volumes/TUF ESD-T1A Media/dsh-plugins/for-free」。

## 设置页（一页）

设置 → 插件 →「For Free」：

- **模型清单**：模型名、id、车道（免费车道 / Kilo）、上下文长度、状态（可用 / 地区受限 / 额度受限 / 不可用 / 未检测）、首字与总延迟
- **刷新清单**：向上游重拉模型目录。**检测可用性**：对每个模型发一次真实请求来判定，会消耗免费额度，手动点才跑
- **开关**：总开关（关掉后选择器里一条都不出现）、地区受限模型是否单独分组
- **设置**：后台刷新间隔（分钟）、默认输出上限、**额度用完自动换模型**
- **自动链**：选择器里的「自动」是一个虚拟模型，内部按可用性排序（每条车道取前 6 个），
  某个模型额度用完/地区受限时自动换下一个，你看不到中间过程

数据在 `~/.dsh/for-free/`：`settings.json`（设置）、`availability.json`（探测结果）、`stats.json`（用量）、`catalog.json`（清单缓存）、`session-map.json`（会话 → 上游会话 id 的映射）。

## 两条车道的边界

- **Kilo 免费池的模型卡声明 `mayTrainOnYourPrompts: true`**：发给它的 prompt 可能被上游记录并用于改进服务。适合写代码、查资料、跑脚本；客户资料、密钥、私密文档别往这条车道发。
- **opencode 免费车道靠客户端指纹过闸**，上游改一次指纹就全部 403/429。原包（`dsh-our-free-model`）为此写过四轮适配（2026-09-24、10-14、10-16、10-17）。坏了看「车道挂了怎么办」。
- 两条车道都不提供 SLA。它们能用的前提是上游继续放行匿名免费额度。

## 额度还剩多少？怎么知道？

**先说实话：上游不给数字。** 两家都没有"剩余 37%"这种接口，任何插件都拿不到。

- **opencode 免费车道**：额度按**出口 / 池**计算，不是每个模型一份。用完回 `429 FreeUsageLimitError`，
  同时给一个 `Retry-After`。2026-10-28 实测抓到的值是 37728 秒，换算后恢复时刻正好是
  **北京 08:00（UTC 00:00）**——也就是说它按天重置。**一个模型受限，整条车道这一轮都受限。**
- **Kilo 免费池**：没有配额概念（`cost = 0`），只有速率限制；被限流时同样不给剩余量。

所以设置页能给的是三样，都是实测或本地计数：

| 看什么 | 在哪 | 说明 |
|---|---|---|
| 每个模型现在能不能用 | 模型清单「状态」列 | 可用 / 地区受限 / 额度受限 / 不可用 / 未检测 |
| 额度受限时**什么时候恢复** | 状态列下方「约 HH:MM 恢复」+ 顶部提示条 | 由上游 `Retry-After` 换算，是本机算得出来的唯一硬时间 |
| **本机已经用掉多少** | 「本地用量」区块 | 请求数、失败数、输入 / 输出 / 思考 tokens、按模型的调用次数与生成速度 |

**想知道现在的额度状态**：点「检测可用性」。它只打 opencode 车道的免费模型（Kilo 行不探测），
429 不消耗额度、成功才花一点点。结果会写进 `~/.dsh/for-free/availability.json`，重启不丢。

### 额度用完了，正在跑的任务会怎样

**会立刻失败结束，不会卡住。** 具体说：

- 429 是**终止性**失败：`providerRetryPolicy` 的 `retryableCodes` 里故意不含 `RATE_LIMIT`
  （上游给的 `Retry-After` 是往上走的，自动重试只会把一次墙撞成三次、还多花时间）。
- 这一轮以错误结束，界面显示失败原因；**对话历史、文件改动、工具结果都还在**。
- 换一个模型、说一句「继续」，就从断点接着做——不需要重开会话。

**现在有自动链就不会撞上这个了**：选择器里选「自动」，第一个候选失败（在出正文之前）会被
整段丢弃并自动换下一个，调用方（内核）看不到中间过程。实测：`mimo-v2.6-flash-free`（429）→
`kilo-auto/free`，同一次请求里换过去，正文正常返回、正常结束、耗时 4.9 秒。

边界：**正文已经开始输出之后**才失败，就不换了——那属于这一轮真的失败（已经交给你的文本不能撤回），
`src/adapter.js` 的 `runCombo` 注释里写了这个 commit 规则。



### 上游发新版了（作者更新 / 修了指纹）

把新包解压到任意目录（比如 `不推送/upstream/package-2.7.3/`），三步：

```bash
cd for-free
node scripts/upstream-diff.mjs <新包目录>          # 只看，不写任何文件
node scripts/upstream-sync.mjs <新包目录> --apply  # 白名单同步 + 重放补丁
node test/smoke.mjs && node test/live.mjs          # 冒烟 + 实网
```

`upstream-diff.mjs` 回答四个问题：版本变了没、20 个同步文件里哪些真变了、**会失效的指纹**（UA / 工具定义 / 会话编码 / 端点 / 网关请求头）从什么变成什么、我们的补丁还能不能套上去。它还会列出上游新增的文件（可能是新车道，也可能不用管）。

`upstream-sync.mjs` 只碰 20 个白名单文件。某个文件的补丁套不上时，**那个文件保持原样**、以退出码 2 报告，其余照常写——不会留下半成品。写完更新 `upstream.lock.json`（上游版本 + 每个文件的上下游哈希 + 12 项指纹快照），下次 diff 就有了基线。重复跑是幂等的（对同一版本第二次跑报 0 个变化）。

### 补丁是什么，为什么要它

我们对上游文件的每一处改动都声明在 `scripts/patches.mjs` 里，以**上游原文**为锚点：反代 base 改成运行时函数、`SETTINGS_INITIAL` 砍到我们自己用的字段、`forward.js` 的 `toOpenAiUsage` 内联、品牌改名。

上游一旦动了那段代码，补丁就失败，diff 会指到具体条目和原因。处理顺序：打开上游对应文件 → 找现在等价的代码 → 改 `find` → 重跑 diff。

**改代码不改补丁 = 下次同步被覆盖。**所以加功能时：先改代码、跑通、再把改动回落成一条补丁（`find` 用上游原文）。

### 直连被限流或地区拦住：反代

设置 → For Free →「反代（留空 = 直连官方）」填两个地址：

- **opencode 反代地址** → 转发到 `https://opencode.ai`
- **Kilo 反代地址** → 转发到 `https://api.kilo.ai/api/gateway`

转发端的要求只有三条：路径原样、请求头原样、请求体原样。**不要改写 `user-agent` / `authorization` / `x-opencode-*`**——opencode 的指纹门逐字比对，改一个头就是 403。

可跑的样板在 `node test/relay.mjs`：30 行本地转发服务器 + 8 项断言（证明指纹头能穿过反代）。把它换成 Cloudflare Worker、nginx、VPS 同理，填地址即可，不用改代码。

保存后插件会按新地址自动重拉一次清单。也支持环境变量 `FOR_FREE_BASE` / `FOR_FREE_KILO_BASE`，优先级：设置页 > 环境变量 > 官方地址。

### 现象 → 原因 → 动作

| 现象 | 含义 | 动作 |
|---|---|---|
| 状态「额度受限」，模型还在选择器里 | 这个出口的免费额度用完（429 FreeUsageLimitError） | 换出口 / 配反代 / 等恢复；Kilo 通常不受影响 |
| 状态「地区受限」 | 上游按地区拒绝（403 RegionError） | 同上 |
| 状态「不可用」且详情是 403 FreeTierError | 指纹过不去了（上游改了校验） | 看 diff 的指纹对比，同步新版 |
| 整个列表空 | 两条车道都没拉到清单 | 点「刷新清单」；还空就先查本机网络和反代地址 |
| 反代填了反而全失败 | 转发端改了头 / 丢了 path 前缀 / 没转发 POST 体 | 用 `test/relay.mjs` 的转发服务器对照一次 |

### 什么时候该把人叫来

- diff 报「补丁失败」：上游重构了我们改过的那段
- 上游新增了文件：可能是新车道（要不要接是产品决定）
- 指纹变了但新值看着可疑：比如工具定义的 description 被重写，需要我们判断是上游业务变化还是我们的移植要跟着改

## 和原包的关系

从 [`dsh-our-free-model`](https://github.com) 2.7.2（MIT）精简衍生。**保留的**是验证过的整车：请求编码（chat / responses / messages 三种线形）、流式解析、指纹适配、可用性探测、思考档位、Kilo 车道、降级链（`src/combos.js`，现在用作自动链）。

**删掉的**（连同它们的数据字段与界面）：

| 删掉的东西 | 为什么 |
|---|---|
| 十个账号渠道（LobsterAI / Qoder / TRAE / Cline / Loomy / Raccoon / MiniMax / ZCode / Gemini / 独立服务） | 要登录十个平台，白嫖额度不值得这个维护面 |
| EAC 协付车道（宿主指纹闸门 + GitHub star 校验） | 要 star 授权，且只在特定桌面宿主里存在 |
| 聚合渠道（76 家自带 Key） | 有 Key 就该用官方插件，不需要中介 |
| 本地 OpenAI 网关 + Anthropic 端点 + 局域网中继 | 给别的工具用，跟我们自己用没关系 |
| 出口中继（订阅链接 → mihomo → 本地中继） | 直连就够；要换出口用系统代理 |
| 降级链（combo） | **保留并改造成「自动链」**：`combo:auto` 按可用性排序，额度用完自动换下一个 |
| 省 Token（RTK 压缩 + 两族提示词） | 会改写发给模型的内容，不是接入问题 |
| 公告推送、自升级、热重载 | 本地 `link:` 源码插件，改一行就生效 |
| Windows x64 引擎分片（33.5 MB）与 Magpie 引擎 | macOS 上用不到 |
| 11 页客户端界面 | 主页换成一张清单 |

体积：安装占用 38 MB → 约 360 KB；源码 27,659 行 → 约 7,300 行（其中约 6,000 行是原样搬过来的协议层）。

node test/smoke.mjs   # 假 ctx 起宿主半身：注册、API、刷新、设置写入，13 项断言
